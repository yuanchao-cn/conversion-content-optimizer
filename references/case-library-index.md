# 优秀案例索引

本目录存放可复用的营销转化型内容案例。**只引用这里真实存在的案例**，禁止虚构案例 ID 或来源。

## 案例库现状

当前案例数：0。案例库为空时，按 `methodology.md` 与 `knowhow-checklist.md` 做基线检查，并在报告里写明「当前案例库无同类案例」。

**市场版注意**：本索引是随包发布的静态基线，只放已公开或已获授权的案例，不得含客户名、内部链接或未公开原文。
持续新增的案例不放这里，改放公开 URL 指向的云端 JSON 的 `cases` 数组（结构见 `SKILL.md` 的「知识源」章节），通过 `scripts/fetch_knowledge.py` 在运行时拉取。

## 检索规则

Step 4 选案例时按以下顺序匹配，最多取 3 个：
1. 行业相同 + 营销目标相同
2. 行业相同 + 目标不同（注明目标差异）
3. 行业不同 + 结构问题相似（注明「跨行业类比」）

## 新增案例流程

1. **（市场版推荐）** 按 `case-template.md` 的字段结构，把案例追加到公开 URL 的云端 JSON `cases` 数组，更新 `version` 与 `updated_at`。用户无需重装 Skill 即可获取。
2. 仅当案例已公开且要随包分发时，才复制 `case-template.md` 为 `references/case-<行业缩写>-<序号>.md`，并在上方索引表追加一行；此时需在 `SKILL.md` frontmatter 递增 `version` 并重新打包上架。
3. 若案例与 `methodology.md` 的基线做法冲突，在案例卡片的「与基线差异」里写明，用户材料优先。

## 录入质量要求

- 必须写明来源（链接/出处/提供人）与录入日期，无法溯源的材料标为「用户提供，未公开来源」。
- 「为什么优秀」至少 3 条，每条对应一个可观察的结构动作，不能只写「写得好」。
- 「不可迁移部分」必填：避免把特定品牌的资源优势当成通用方法。
